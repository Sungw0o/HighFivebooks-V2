# JPA 도서 목록 조회 반복 측정

## 문제 상황

도서 157,118건에서 collection `EntityGraph`와 `Pageable`을 함께 사용하면 Hibernate가 메모리 pagination을 수행해 목록 조회가 지연됐습니다.

## 측정 조건

| 항목 | 값 |
|---|---|
| 측정 일시 | 2026-08-13 08:02~08:14 KST |
| 실행 환경 | Docker Desktop, MySQL 8.4, k6 0.53.0 |
| 데이터 | 동일 MySQL 데이터, `book` 157,118건 |
| 요청 | `GET /api/books?page=0&size=1` |
| 부하 | 1 VU, 60초 |
| 반복 | 개선 전후 워밍업 1회 후 각 5회 |
| 집계 | 각 실행의 `book_list_duration` p95, 5회 중앙값 |

## 검증 결과

| 지표 | Before | After |
|---|---:|---:|
| 5회 p95 중앙값 | 2,913.60ms | 26.96ms |
| p95 범위 | 2,828.28~3,886.12ms | 24.92~31.24ms |
| HTTP 실패율 | 0% | 0% |

p95 중앙값 기준 약 108.07배 개선됐습니다. 원시 k6 JSON은 `perf/results/book-list-*-run-*.json`에 보관합니다.

## 한계

- 로컬 단일 호스트 측정이며 네트워크 지연과 운영 트래픽을 포함하지 않습니다.
- 개선 전 처리량이 낮아 실행별 요청 수가 다르므로 지연시간 중앙값 비교로 한정합니다.
- 캐시·JIT 영향을 줄이기 위해 워밍업했지만 완전히 통제하지는 못했습니다.
